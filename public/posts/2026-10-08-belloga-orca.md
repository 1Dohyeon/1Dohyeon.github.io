# Belloga가 오픈소스 Orca에서 가져온 것과 가져오지 않은 것

Belloga는 오픈소스 데스크톱 앱 [Orca](https://github.com/stablyai/orca)(MIT)를 참고했고, 일부 코드와 디자인을 가져와 고쳤습니다. 남의 코드를 가져오면 개발은 빨라지지만, 쓰지 않는 기능과 그 기능에 얽힌 구조까지 함께 들어옵니다. 그래서 가져올 때마다 **무엇을 가져오고 무엇을 가져오지 않는지**를 결정 기록(ADR)으로 남겼습니다. 이 글은 그 세 건을 정리합니다.

---

## 가져올지 판단한 기준

세 건 모두 같은 질문을 거쳤습니다.

1. **Orca가 이미 같은 문제를 풀었는가?** 직접 만들면 경계 사례와 테스트를 처음부터 다시 쌓아야 합니다.
2. **필요한 부분만 떼어 낼 수 있는가?** 쓰지 않는 기능과 얽혀 있으면, 걷어 내는 비용이 새로 쓰는 비용보다 클 수 있습니다.
3. **가져온 뒤 Belloga의 원칙과 부딪히는가?** 색 규칙, 모듈 경계, 보안 경계처럼 이미 정한 원칙이 있습니다.

---

## 1. 채팅 화면: 7만 줄 중 5,000줄만

### 문제

Claude 탭은 채팅 뷰 아래에 터미널을 두고, 터미널을 Claude Code 입력 박스만 보이게 잘라서 입력을 받았습니다. 자르기는 터미널 화면의 가로줄을 찾아 입력 박스 위치를 추측하는 방식이라, Claude Code 화면이 조금만 바뀌어도 깨졌습니다. 채팅 뷰는 대화 기록(transcript)을 단순하게 해석해서 도구 결과, diff, 이미지를 보여 주지 못했습니다.

### 검토한 대안

| 대안 | 판단 |
| ---- | ---- |
| 지금 구조 유지 | 입력이 Claude Code 그대로라 기능 손실은 없지만, 자르기가 화면 모양 추측에 기댐 |
| Agent SDK로 Claude를 직접 구동 | 메시지를 구조화된 이벤트로 받지만, statusLine 같은 TUI 기능이 빠지고 "터미널에서 친 claude"라는 요구와 어긋남 |
| Orca Native Chat 전체 이식 | 약 420개 파일, 7만 줄이고 대부분 SDK, WSL, 원격, 다른 에이전트 지원이라 쓰지 않음 |
| **Claude와 로컬 부분만 이식 (채택)** | 약 60개 파일, 5,000줄. 검증된 감시, 해석, 전송 규칙을 쓰면서 Claude는 터미널에서 그대로 돎 |

### 가져온 방식

- Claude는 지금처럼 터미널(pty)에서 실행하고, 채팅 화면 아래의 자체 입력창이 pty에 씁니다. 하네스, 훅, statusLine은 그대로 동작합니다.
- 가져오지 않은 것을 명시했습니다. Agent SDK 세션, WSL과 원격 런타임, Claude 외 에이전트, 가상 스크롤, 음성 입력, 모델 선택기, 리치 텍스트 편집기, Orca의 앱 상태 관리와 Tailwind입니다.
- 권한 요청은 기존 훅에 필드만 더해 카드로 답하게 하고, 훅 이벤트는 늘리지 않았습니다.
- 나중에 Orca를 다시 가져와 맞출 때를 위해, Orca 원본 경로와 이식 방식(복사, 축소, 재작성)의 대응표를 계획 문서에 남겼습니다.

대화 기록 형식과 TUI 키 입력은 공개 API가 아니라서, Claude Code가 바뀌면 깨질 수 있다는 점은 결과로 받아들였습니다. 깨져도 터미널로 전환하면 계속 쓸 수 있습니다.

## 2. 터미널 링크: 탐지기는 가져오고, 여는 쪽은 새로 쓴다

### 문제

Claude가 터미널에 출력한 파일 경로나 URL을 Ctrl+클릭으로 열고 싶었습니다. 경로 탐지는 생각보다 어렵습니다. 공백이 든 경로, `:줄:열`, `file://`, 괄호가 든 프레임워크 경로를 다뤄야 하고, TUI가 줄 끝에서 경로를 끊어 다음 줄에 이어 쓰는 경우도 있습니다.

### 결정: 반으로 나눴다

- **가져온 것**: 경로 후보 추출(VS Code의 탐지기를 Orca가 포팅한 것), `:줄:열`과 `file://` 해석, 줄바꿈으로 끊긴 경로와 URL 잇기. 순수 함수는 `src/shared/`에 두었습니다.
- **새로 쓴 것**: 파일을 여는 쪽입니다. Orca의 열기 코드는 상태 저장소, SSH, WSL, 원격 다운로드, 앱 안 브라우저와 한데 얽혀 있어 걷어 내는 비용이 새로 쓰는 비용보다 컸습니다.
- 공식 애드온(`@xterm/addon-web-links`)은 쓰지 않았습니다. 물리 줄만 알아서 TUI가 끊은 URL을 놓칩니다.

### 터미널 출력은 신뢰할 수 없는 입력이다

탐지는 가져왔지만 열기 판정은 Belloga의 보안 경계에 맞춰 새로 정했습니다. 클릭 한 번으로 프로젝트 밖 파일이나 실행 파일이 열릴 수 있기 때문입니다.

- 경로 풀기와 열기 판정은 **main 프로세스**가 symlink를 푼 실제 경로로 합니다. 렌더러는 파일 시스템에 접근하지 못하고, 경계 판정을 신뢰할 수 있는 쪽은 main입니다.
- 프로젝트 안의 텍스트 파일은 앱 탭으로 열고, 프로젝트 밖 파일은 시스템 기본 앱으로 넘깁니다.
- **실행 파일을 시스템에 넘길 때는 실행하지 않고 파일 관리자에서 위치만 보여 줍니다.** 실행 권한, `.app`, `.sh` 같은 파일이 클릭 한 번에 실행되지 않게 하려는 것입니다.
- 바이너리 판정은 git과 같이 앞 8,000바이트에 NUL 바이트가 있는지로 합니다.
- URL은 http, https만 엽니다.

## 3. 상태 표시줄: 디자인은 그대로, 원칙과 부딪히는 곳만 예외로

상태 표시줄은 기능과 디자인을 모두 Orca 다크 테마의 치수와 색 그대로 가져오기로 했습니다. 그런데 Orca는 사용량이 60% 이상이면 노랑, 80% 이상이면 빨강을 씁니다. Belloga는 "유채색은 세션 상태와 로고에만 쓴다"는 색 규칙(ADR)이 있어서 부딪혔습니다.

- 사용량 막대를 무채색으로 두면 원칙은 지키지만, 한도에 가까운지를 색으로 알 수 없습니다.
- 그래서 **사용량 등급색 두 개를 색 규칙의 예외로 명시**하고, 그 예외를 새 ADR에 적었습니다.
- 기존 위험색(`--danger`)을 빌려 쓰지 않고 `--usage-warning`, `--usage-critical` 토큰을 따로 두었습니다. 뜻이 다른 상태가 같은 토큰을 쓰면 한쪽을 바꿀 때 다른 쪽이 따라 바뀌기 때문입니다.
- Orca의 글자체(Geist)는 가져오지 않았습니다. 한글을 담지 않고, 상태 표시줄만 다른 글자체를 쓰면 앱 안에서 어긋납니다.

## 저작권 고지

가져온 부분은 저장소의 `THIRD_PARTY_NOTICES.md`에 Orca와 VS Code 항목으로 고지했습니다. 파일마다 주석을 다는 대신 한 곳에 모았고, 가져올 때마다 해당 ADR에서 이 고지를 가리킵니다.

---

## 정리

- 가져올 때마다 "이미 풀었는가, 떼어 낼 수 있는가, 원칙과 부딪히는가"를 따지고, 가져오지 않은 것까지 ADR에 적었습니다.
- 채팅 화면은 7만 줄 중 필요한 5,000줄만, 터미널 링크는 탐지기만 가져오고 여는 쪽은 보안 경계에 맞춰 새로 썼습니다.
- 디자인을 그대로 가져오면서 원칙과 부딪히는 곳은 조용히 어기지 않고 예외로 명시했습니다.
